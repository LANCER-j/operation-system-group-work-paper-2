# 待验证结论与实验方案

状态：实验刚刚开始进行；本文件记录假设和验证方案，暂不提交结果或结论。范围为论文第 5.1 节，纸面页码 89–91（PDF 第 6–8 页）。

## C1：竞争负载下的运行机会与公平性

**原文依据：第 5.1 节、Figure 1，必要时参考 Figure 2 的机制解释。** 在原文负载中，CFS 允许计算密集型 Fibo 在数据库运行期间继续推进；ULE 优先处理交互式数据库线程，可能使 Fibo 长时间无进展。

实验设计：Fibo 先启动 7 秒，然后启动 80 线程 Sysbench/MySQL 读写负载。两类负载均绑定客户机 CPU 0，控制与采样程序放到另一核心。分别使用独立 CFS 与 ULE 内核，其他配置固定，每种至少 3 轮。

观测指标：

- Fibo 和数据库的累计调度驻留时间（scheduled residency）随墙钟时间的曲线。
- 两类负载共同存活期间，Fibo 驻留时间增量 / 共同存活墙钟时长。
- 0.1 秒采样分辨率下，Fibo 最长连续零增长区间。
- 若所有轮次都覆盖同一时窗，补充数据库启动后固定前 20 秒比较；不够长的轮次应明确标记，不能裁短冒充同长窗口。

判定：若 CFS 下持续推进而 ULE 下出现稳定、可重复的强烈抑制，支持这一配置下的定性差异；若两者均持续推进且份额接近，则不支持该配置下预期差异；若测量丢失、工作负载过早退出或条件不匹配，记为证据不足。最终判定需结合三轮差异与变异程度，不预设必须得到某一数值。

限制：有限时长的无进展不能证明无限饥饿（unbounded starvation）；退出后的平坦曲线不能算饥饿。调度驻留时间可能包含中断与客户机被暂停的时间，不等同于严格的进程 CPU 时间。两侧统一使用跟踪口径；不能把 ULE 的零进程计数直接解释为没有执行。

## C2：数据库性能与计算任务进度的取舍

**原文依据：第 5.1 节、Table 2，结合 Figure 1。** 在该竞争负载中，ULE 对数据库线程的优先处理可能提高数据库吞吐量、降低平均事务延迟，同时挤压计算任务的运行机会。

在 C1 同一批试验上读取 Sysbench 的事务吞吐量（transactions/s）和平均延迟（ms），报告每种条件至少三轮的均值与样本标准差（分母 n−1）。Fibo 的墙钟完成时间仅作为本组辅助指标，不直接视为原文 Table 2 的 Fibo runtime。

判定：吞吐量提高与平均延迟降低且运行机会指标一致时，支持这一配置下的预期取舍；方向不一致时分别报告，不能将一个指标替代整体结论。检查每轮返回码、事务数、忽略错误与重连计数；程序成功退出不等于数据库零错误。

数据库整体吞吐量可能包含 Fibo 提前结束后的单独运行阶段。应记录该阶段；若存在，整体吞吐量不属于严格相同的持续竞争窗口。可以在正式批次前统一调整 Fibo 固定工作量，并将双方全部重跑；禁止对不同调度器使用不同工作量。

## 固定条件与输出计划

| 条件 | 计划值 |
|---|---|
| Fibo | 递归 fib(40)，重复 100 次，`-O2` 编译，固定工作量 |
| 数据库 | MySQL 5.7.42；Sysbench 1.0.11；`oltp_read_write.lua` |
| 规模 | 单表 10000 行；10000 个事务事件；关闭时间限制 |
| 并发 | 主对照 80 线程；数据库连接上限始终固定为 112 |
| 分组 | Fibo 与数据库分别放入 `cpu.shares=1024` 的 CPU cgroup，不设置硬配额 |
| 采样 | 同一 `sched_switch` 方法，间隔 0.1 秒；不接受丢失事件的轮次 |
| 运行 | Fibo 前导 7 秒；各条件至少 3 轮；每轮独立数据库目录 |

参数为基于论文描述的重建，其中 Fibo 实现、数据库规模和具体分组并未由原文完整给出。环境与偏差见 [environment.md](environment.md)。未来每个报告数字都需对应实际日志和计算入口。

## 扩展预案：仅改变线程数

在 ULE 下从 80 线程改为 40 线程，其他参数不变，尤其 `max_connections=112`；至少重复 3 轮。动机是检查并发程度是否影响数据库性能与 Fibo 的运行机会。

```bash
sudo python3 experiment/run_experiment.py --scheduler ule --threads 40 --runs 3 \
  --output "$PWD/results/ule-extension40"
```

这是本组扩展问题，不是第三条原论文结论。只测试 ULE 40 线程时，不能推出 CFS 与 ULE 在 40 线程下谁更优。本周仅提交设计与执行代码。
